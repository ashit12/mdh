mdh matching-engine baseline: allocation behaviour and memory footprint

=== Allocations per matching-engine operation =================================
Averages over a batch, so a fractional count is real (amortised container growth),
not a rounding artefact. "net bytes" is allocated minus freed: it is what the
operation leaves behind on the heap, and should be ~0 for anything that does not
grow the book.

=== Memory footprint of a resting book ========================================
Directly measured, not estimated: live bytes is (allocated - freed) across building
the book, using the platform allocator's own reported block sizes, so allocator
rounding is included. RSS delta is a coarse cross-check that includes page-level
granularity and the process's other state.
